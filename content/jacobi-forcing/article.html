What if LLMs could generate multiple tokens at once?

Standard autoregressive decoding generates text one token at a time, with each prediction conditioned on the tokens already generated. Jacobi decoding offers an alternative: predict a block of tokens in parallel, then refine those guesses over successive passes. Jacobi Forcing trains models on their own intermediate drafts so the decoder can accept more tokens per pass.

The decoder starts with a block of token guesses. In each iteration, every position is recalculated using the previous iteration’s values to its left. The third position, for example, uses the old guesses for positions one and two; it doesn’t wait for their updated values. This lets the model update the whole block in one forward pass.

Causal attention is preserved: each token only attends to positions to its left. The parallelism comes from using provisional values at those positions, rather than waiting for each one to be confirmed.

Matching a token at a later position isn’t enough to accept it. The decoder verifies and commits a contiguous prefix from the left; later guesses stay provisional until their preceding context is confirmed.

The difficult part is making those early guesses useful. A model normally learns to predict the next token from a correct prefix. In our example, it now has to make progress while earlier guesses still say “dog” instead of “cat”. Simply updating more positions at once doesn’t teach it how to handle that context.

Jacobi Forcing trains for this situation. The researchers collect the model’s intermediate drafts and train it towards the converged answer, including when earlier blocks are still unfinished. Ordinary next-token training stays in the mix to help preserve quality. The aim is to make more of the parallel guesses survive verification, so fewer passes are needed.

The decoder can also work on later blocks while the first is being confirmed (multi-block decoding), and reuse promising sequences from drafts it previously rejected (rejection recycling). Those sequences still have to be verified. Because attention stays causal, it can reuse the KV cache for the confirmed prefix instead of recomputing it. The authors’ explanation shows how these pieces fit together.

Speculative decoding already tackles the same bottleneck. In its classic form, a smaller model drafts a continuation and the main model checks the proposed tokens together. Some newer systems use a draft head instead of a separate model. With the appropriate verification and sampling rule, lossless speculative decoding preserves the target model’s output distribution. It accelerates the model we already have.

Jacobi Forcing instead trains the main model to make its own parallel predictions. Its advantage is avoiding a separate drafting stage and its compute, memory and coordination overhead. That work moves into fine-tuning and a compatible decoder. It keeps the causal transformer architecture, but it doesn’t guarantee the original model’s answers stay unchanged.

The published paper’s A100 HumanEval comparison uses the same Qwen2.5-Coder-7B-Instruct backbone. EAGLE-3 reaches 127.2 tokens/s and HASS 95.2, both retaining the original 87.8% first-attempt success rate. Jacobi Forcing with its decoder refinements reaches 163.9 tokens/s at 83.5%. It’s faster in this setup, but the speculative methods preserve more of the original quality. Drafting and verification overhead also help explain why accepting more tokens per target-model pass doesn’t necessarily produce higher throughput.

The useful comparison within the same model family is the HumanEval ablation. The original model generated 41.3 tokens per second; plain Jacobi decoding managed 39.9, making it slightly slower. Jacobi Forcing training brought that to 159.5, and the two decoder refinements to 163.9. Most of the gain came from training the model to produce better parallel drafts.

The coding result is a speed–accuracy tradeoff. HumanEval throughput rises by 3.97×, while first-attempt success falls from 87.8% to 83.5%: a 4.3 percentage-point drop. MBPP loses 3.9 points. More answers arrive sooner, but more of those first attempts fail their checks.

Verification still checks agreement with the fine-tuned model. Fine-tuning can change what that model predicts, which explains why its answers can differ from the original checkpoint. The ordinary training objective helps retain its earlier capabilities, without guaranteeing identical answers. Nor is there a fixed accuracy penalty for parallel decoding: GSM8K loses one point in these tests, while MATH improves by 0.4 points.

Whether that tradeoff helps depends on the application. Interactive coding and SQL agents are plausible candidates: they can spend several rounds generating an answer, running it, receiving feedback and trying again. If generation takes a large share of each round, shortening it could reduce the whole loop’s latency. Tests, execution and other checks can reject bad candidates, though they won’t catch every mistake.

The saved time could also leave room for another attempt when the first fails. That’s a possibility to test, not something the pass@1 table proves. Repeated attempts can make the same mistake, and checking or retrying has its own cost. A nearly fourfold decoding speedup doesn’t automatically mean four times as many successful tasks.

Long responses give the decoder more time to save. A five-token classification answer offers much less room, especially if retrieval, tool calls or prompt processing dominate the request. Lower latency also doesn’t guarantee lower serving cost: parallel passes do more computation, and a busy server may already be using the GPU well. The paper’s separate B200/vLLM results use one request at a time; they aren’t a guarantee for a heavily batched service.

An agent that can run tests, check a query, and revise its answer is a sensible place to start. If we can turn shorter generations into shorter feedback loops, the speed–accuracy tradeoff may be worthwhile. When the original model’s behaviour must stay unchanged, lossless speculative decoding is the better fit.
